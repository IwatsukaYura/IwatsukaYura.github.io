Terraform の挙動は state ファイル（`terraform.tfstate`）を中心に理解すると分かりやすい。

## state が持つもの

- 実リソースと設定（`.tf`）のマッピング（どの定義がどの実リソースか）。
- 各リソースの属性のキャッシュ。
- 依存関係のメタ情報。

`plan` は「設定・state・実リソース」の3つを突き合わせて差分を計算する。

## リモート state とロック

- ローカル state はチーム作業で壊れやすい（上書き・コンフリクト）。
- S3 + DynamoDB（ロック）などのリモートバックエンドにして、
  - 複数人で同じ state を参照できるようにする。
  - **ロック**で同時 apply を防ぐ。

## 注意点

- state には機密情報が平文で入りうる。バックエンドの暗号化・アクセス制御は必須。
- 手動でリソースを変更すると drift が発生する。`plan` で検知し、取り込むなら `import` / 構成側を直す。
